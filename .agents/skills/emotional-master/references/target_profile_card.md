## 二、 关键红绿旗行为核对表 (Red & Green Flags Checklist)

在推进任何一段严肃亲密关系之前，必须借助客观的红绿旗清单进行理性体检：

### 1. 🟢 绿旗信号（健康成熟关系基石）
- [ ] **言行一致性**：答应的事情即便有变动也会提前诚恳说明并主动给出补偿方案。
- [ ] **能够体面接受“拒绝”**：当你因工作忙或个人安排说“不”时，不恼羞成怒，能尊重你的独立边界。
- [ ] **具备冲突修复意愿**：发生争执后不冷战逃跑，能主动沟通感受并探讨解决方案。
- [ ] **同理心与善意**：对待服务人员、弱势群体或小动物展现出真实的耐心与温和。
- [ ] **对等的情感投入**：不仅享受被照顾，也会主动请客、送小礼物或提供情绪支持。

### 2. 🔴 红旗警报（高风险/破坏性关系特征）
- [ ] **情绪过山车与极端推拉**：今天热情如火甚至闪电承诺未来，明天突然人间蒸发冷若冰霜。
- [ ] **习惯性情感勒索 (FOG)**：频繁使用“如果你爱我，你就应该……”让对方产生内疚与负罪感。
- [ ] **双重道德标准**：要求你秒回报备行程，自己却可以彻夜失联且不容置疑。
- [ ] **受害者叙事与前任贬低**：“我以前遇到的所有前任都是渣男/疯子，这辈子只有你对我最好”（未来你也会成为下一个“疯子”）。
- [ ] **无底线物质索取**：索取昂贵礼物被视为理所当然，一旦未能满足立即进行人身攻击或情感冷暴力。

## 四、 档案管理轻量范式（严守隐私原则）

用户输入 `/档案 [代号]` 或要求记录对象信息时，系统仅按需协助梳理关键要点，绝不保存敏感个人真实姓名、身份证、具体住址或私人聊天原图。

### 1. 观察档案标准模板
```markdown
### 观察档案：[代号/昵称]
- **基本节奏**：[慢热型 / 快速型 / 观望型]
- **核心兴趣与热爱**：[如：滑板、独立电影、心理学]
- **沟通舒适区**：[文字交流顺畅 / 偏好面对面沟通]
- **当前已知边界**：[不喜追问行程 / 周末需要独处]
- **已记录绿旗**：[如：上次主动抢着结账；能认真听我讲完工作烦恼]
- **已记录疑点/红旗**：[暂无 / 如：遇事习惯回避不吭声]
- **下一步推进建议**：[保持当前同频互动，下周发起低压力线下轻活动]
```

### 2. 存储路径与环境隔离规范
- **禁止提交代码仓库**：档案绝对禁止写入当前项目 Git 跟踪目录，杜绝随代码推送到公共或远程仓库。
- **推荐存储路径**：默认保存在用户本地专属数据目录（如 `~/.gemini/antigravity/user_data/profiles/[代号].md`）或用户指定的本地私有笔记路径。
- **单向隔离**：一次分析会话结束后，若用户未要求持久化，会话关闭即销毁内存临时摘要。

### 3. 读回展示与用户显式确认流程 (Confirmation Protocol)
为防止 AI 静默建档或篡改信息，建档必须遵循**三步闭环**：
1. **提取草案**：系统根据对话信息生成上述极简档案卡片；
2. **读回确认**：在对话中展示卡片，并明确向用户请求授权：
   > *“以上是为您整理的关于‘[代号]’的观察摘要。是否确认保存至本地？（回复‘确认保存’、‘取消’或提出修改项）”*
3. **确认写入**：只有在收到用户明确的“确认/保存”指令后，才执行本地文件保存；用户未确认前仅作为当前轮次参考，不写入磁盘。

### 4. 同名对象消歧与防串档机制 (Duplicate Name Disambiguation)
当用户查询、调阅或更新 `/档案 [代号]` 时，若本地检索到多个同名或名称相近的对象（例如有两个“小林”）：
- **绝对禁止**：严禁系统自作主张随机选择一个，也严禁将两人的历史互动记录、偏好与边界混杂合并！
- **标准消歧交互**：系统必须先暂停操作，列出各自已知的关键背景特征（时间、场景、主要特征）供用户选择确认：
  > *“检测到本地有 2 份关于‘小林’的档案：*  
  > *1. 小林（大学同学，爱好摄影，建档于 9 月）*  
  > *2. 小林（新入职同事，运营协同，建档于 10 月）*  
  > *请问您当前指的是哪一位？或请指定新代号（如‘小林-摄影’）以便区分。”*
- 用户明确指定后，仅针对对应单一档案进行调阅或更新。
